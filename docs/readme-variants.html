01 / Straight to the point

Minimal Recommended

Short declarative prose. A quick scan answers what it does, how to install it, and what to watch out for.

pi-prompt-history

Persistent prompt search for Pi. Press Ctrl+R to find a previous prompt and load it into the editor without sending it.

History spans sessions and Pi processes. Search the current directory by default; press Tab to search all directories. No session resume required.

MVP, not production-ready. Prompts are stored in plain text. Rewrites can lose concurrent appends. MIT licensed; not published to npm.

Install

git clone https://github.com/khiet/pi-prompt-history.git
pi install /absolute/path/to/pi-prompt-history

Restart Pi or run /reload. No npm install required. Try once with pi -e /absolute/path/to/pi-prompt-history.

Tested: Pi 0.85.1 and 0.87.1; Node 22.22.0 and 24.21.0; macOS arm64 locally and Ubuntu in CI. Windows is unverified.

Use

Key / commandAction
Ctrl+R or /historyOpen prompt search
TabSwitch current directory / all directories
Up / DownSelect a prompt
Enter / EscReplace the draft / cancel unchanged
Ctrl+DDelete the selected record after confirmation
/history pause / /history resumeStop / start recording
/history clear cwd / /history clear allClear a scope after confirmation

Search is a case-insensitive literal substring match, newest first, capped at 100 results. Directory scope uses the exact cwd, not the Git root. Restore replaces the entire draft; saved attachments are not restored.

Shortcut

Ctrl+R shadows Pi's session-rename shortcut and triggers a conflict warning. To change history search, create <agent dir>/prompt-history/config.json, then /reload:

{ "shortcut": "alt+h" }

/history remains available if the shortcut conflicts.

Storage & limits

  • Local JSONL: <agent dir>/prompt-history/history.jsonl. Agent dir defaults to ~/.pi/agent; override with PI_CODING_AGENT_DIR.
  • Records interactive TUI prompt text, including steering and follow-up. No attachments, command history, session backfill, or model-context injection. Skips --no-session, print, JSON, and RPC modes.
  • Pause survives reloads and session changes until resume or process restart. It does not stop Pi's own session storage.
  • Compacts to the newest 10,000 records after the process's count exceeds 11,000. Prompts over 32,768 UTF-8 bytes are skipped.
  • No locking; compaction, deletion, and clearing can lose another process's concurrent append. Local filesystems only.

Remove with pi remove /absolute/path/to/pi-prompt-history. History remains until cleared or deleted. Deletion here does not erase Pi session files or backups.

03 / Show the workflow

Workflow-led

A conversational opening, then task-oriented sections. Explains the value without turning into a tutorial.

pi-prompt-history

Find the prompt. Not the session.

You wrote the useful prompt yesterday, in another Pi process. Press Ctrl+R, type a fragment, and bring it back into the editor. Edit it before sending. No need to resume the old session.

This is an MVP, not production-ready. It keeps a plain-text copy of your prompts, and file rewrites can lose concurrent writes. MIT licensed; not on npm.

Add it to Pi

git clone https://github.com/khiet/pi-prompt-history.git
pi install /absolute/path/to/pi-prompt-history

Restart Pi or run /reload. No npm install needed. For a single run, use pi -e /absolute/path/to/pi-prompt-history.

Tested with Pi 0.85.1 / 0.87.1 and Node 22.22.0 / 24.21.0, on macOS arm64 locally and Ubuntu in CI. Windows has not been verified.

Recall, edit, send

Open /history or press Ctrl+R. Type any fragment; search uses case-insensitive literal matching and lists the newest 100 results. Use Up / Down to select and preview.

The picker starts in the current directory, matched by exact cwd rather than Git root. Press Tab to include all directories. Enter replaces the whole draft without submitting; Esc leaves it alone. Attachments from the old prompt do not come back.

Pi already uses Ctrl+R for session rename. This extension takes that key and Pi warns about the conflict. Prefer another key? Create <agent dir>/prompt-history/config.json, then reload:

{ "shortcut": "alt+h" }

/history still works if a shortcut conflicts.

Keep only what you want

Run /history pause before sensitive input and /history resume when done. Pause survives reloads and session changes, but not a process restart. Pi still saves its own sessions.

Use Ctrl+D in the picker to delete one record. Use /history clear cwd or /history clear all for a whole scope. Each asks for confirmation; none erases Pi's session files or backups.

Know where it goes

Prompt text lives in <agent dir>/prompt-history/history.jsonl. The agent directory is ~/.pi/agent unless PI_CODING_AGENT_DIR is set. History is not injected into model context.

  • Records interactive TUI prompts, including steering and follow-up. No attachments, command history, or old-session import. No recording in --no-session, print, JSON, or RPC modes.
  • Compacts to 10,000 records once the process's count exceeds 11,000. Skips prompts over 32,768 UTF-8 bytes.
  • Uses a shared local file without locking. Compaction, delete, and clear can lose another process's concurrent append. Network filesystems are unsupported.

Uninstall with pi remove /absolute/path/to/pi-prompt-history. The history file stays until you clear or delete it.

Editorial notes / Not part of the proposals

What changed, and why

Recommendation: Minimal. It balances a fast first read with explicit safety boundaries. Reference-first suits readers auditing semantics; Workflow-led gives the feature a more memorable introduction.

  • Keep the front door small. Purpose, working install command, controls, config, storage risks, and development checks. Do not make readers parse lifecycle internals before trying the extension.
  • Keep consequential caveats visible. Plain-text secrets, draft replacement, the Ctrl+R conflict, concurrency loss, and the separation from Pi's session storage are not footnotes.
  • Link the evidence rather than reproduce it. Unicode edge cases, the JSONL schema, lifecycle implementation, test inventories, and version-specific capture caveats belong in the detailed reference.
  • Use the tested installation path. This package is private and unpublished. The proposals intentionally do not borrow npm install commands from published extensions or promote the unverified git-install route.

Compatibility claims are carried over from the existing README, not newly tested here. Reference links pin that README to the source commit so these proposals remain usable if the main README changes. On adoption, move the full reference into docs/ and link there instead.
